How to Prevent Estate Sale Pricing and Discount Errors

Make the current price rule easy to apply and a conflicting instruction easy to spot. Researching a value and applying an approved price are different tasks.

By Joel PrentissPublished November 8, 2026

Part 14 of 20 / See the complete operations series

In this guide

  1. Keep one current pricing instruction
  2. Write the rule so two staff members reach the same answer
  3. Check whether discounts replace or compound
  4. Put controls at the point where errors enter
  5. Use an error-proofing review before opening or changing stages
  6. Record errors by type and check the cause

Keep one current pricing instruction

Prevent pricing and discount errors by connecting each item or group to an authorized price, a defined markdown rule, and a current version. Check that labels, signs, published information, and checkout apply the same instruction. Give staff a clear pause-and-escalate route when they disagree.

This guide addresses execution errors: copying the wrong amount, applying the wrong stage, including an excluded item, or using an outdated rule. The pricing-research guide addresses the separate question of how the initial decision is supported.

ASQ’s mistake-proofing resource distinguishes preventing an error from making it immediately apparent. A reminder can help, but a control that blocks an unauthorized state or exposes a mismatch is stronger than simply telling people to pay closer attention.

Write the rule so two staff members reach the same answer

State the starting price, the effective stage or time, the calculation basis, included categories, exclusions, and who may approve an exception. Avoid ambiguous instructions such as “half off now” when some goods use separate terms or an earlier adjustment has already been applied.

Authorized pricing instruction
FieldQuestion it must answerExample boundary
Base amountWhat number does the rule apply to?Original authorized price or another explicitly defined basis
Stage and effective timeWhen is this version active?Current sale stage, with the previous version retired
Scope and exclusionsWhich goods follow the rule?Named groups and clearly identified exceptions
Rounding and entryHow is the amount recorded in the supported system?Agreed method, applied consistently
AuthorityWho may approve a departure?Named role and a recorded decision

A shopper-facing sign should communicate the applicable offer accurately, while staff instructions explain the operational detail. Keep both synchronized. A small note at the register does not repair a misleading sign in another room.

Check whether discounts replace or compound

Consider an invented item with an $80 authorized base price. A 25% reduction from that base produces $60. If the next authorized stage is 50% off the original $80, the price is $40. Applying 50% to the earlier $60 instead produces $30, which is a different rule.

Hypothetical markdown calculation
InstructionCalculationResult
25% off the $80 base$80 × 0.75$60
50% off the original $80 base$80 × 0.50$40
50% off the earlier $60 price$60 × 0.50$30; only correct if this different rule is authorized

These figures are arithmetic examples, not suggested prices or markdown policies. The team needs the actual approved basis. A calculator can faithfully compute the wrong rule if the instruction is unclear.

Test an ordinary item, an excluded item, a group-priced item, and an exception before activating a new stage. If the software and signage use different definitions, stop and resolve the difference rather than asking cashiers to remember an unwritten correction.

Put controls at the point where errors enter

Reduce duplicate entry where practical. If a price must be copied, verify the item reference and amount at the handoff. Retire superseded paper instructions and make the effective version visible. A second sheet labeled “new prices” is not sufficient when nobody knows which one controls.

Use permissions and validation supported by the actual tool. For example, a system may restrict price overrides to an authorized role or require a reason for a change. Test what the control really does before relying on it. If the process is manual, use a clear approval reference and a targeted verification step.

Do not rely on color alone to communicate exclusions or stages. Add readable text or identifiers. A detached colored sticker may not tell the cashier which item, price, or exception it represents.

Keep the change log connected to pricing. A retained item should not remain eligible for checkout just because its old label is still present.

Use an error-proofing review before opening or changing stages

These checks are temporary and are not saved. Print the page or record findings in your own working log.

Pricing and markdown controls

Download the blank price-control log (CSV)

The download contains blank fields and prompts, not automatic calculations or customer information. Adapt it to the records and permissions your firm actually uses.

Repeat the affected checks when a markdown stage changes. Do not assume a successful opening test covers a later configuration change. Give the update an owner and an effective time.

Record errors by type and check the cause

Use a factual defect definition, such as “the amount entered did not match the authorized rule for this item at this time.” Separate that from a customer disagreeing with the chosen price. Count transactions checked and transactions with a confirmed error using a consistent denominator.

Record whether the cause involved an outdated instruction, ambiguous group, wrong entry, or another observed condition. If the cause is uncertain, say so. The root-cause guide shows how to test an explanation before adding another checklist.

Check that a new control does not create an unmanageable checkout delay or inaccessible instruction. The pilot guide helps evaluate accuracy and workload together. The goal is dependable application of an authorized decision, with a visible correction path when something goes wrong.
